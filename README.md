# Что на ужин?

Нативное Android-приложение для подбора блюд из встроенного каталога. Русский и английский интерфейс, поиск по настроению, поводу и другим тегам, варианты блюда в общей карточке. Также доступны поиск по названию и подбор по продуктам. SQLite упаковывается в APK. План проекта описан в [PLAN.md](PLAN.md).

## Разработка Android

Открой папку `android` в Android Studio. Проект использует JDK 17, Gradle 8.11.1 и Android SDK 35. Минимальная версия устройства — Android 8.0.

Готовый двуязычный каталог входит в репозиторий. Gradle упаковывает `dist-data/android/recipes.sqlite` как ресурс приложения. Версия 1.1.0 содержит 490 рецептов, у 355 из них есть теги. Количество порций пересчитывается для структурированных стартовых рецептов. У импортированных рецептов указаны количества и порции из источника.

Чтобы собрать отладочный APK из клона с установленными JDK и SDK, запусти из корня проекта:

```powershell
& '.\android\gradlew.bat' -p android :app:assembleDebug
```

Импортированные рецепты Wikibooks хранят ссылки на исходную ревизию, историю авторства и условия CC BY-SA 4.0. Русский или английский перевод и адаптация входят в каталог. Ссылки доступны в карточке блюда.

Локальный SDK, Android Emulator и образ `DinnerApi35` расположены в `.venv/android-toolchain` на D:. Для запуска с кэшем и временными файлами рядом с SDK используй команду из корня проекта:

```powershell
& '.\.venv\Scripts\python.exe' -m tools.start_android_emulator
```

## Каталог SQLite

Стартовый каталог `catalog/recipes.sqlite` содержит 11 рецептов с общими ID для русского и английского текстов, единицами измерения, базовым числом порций, семействами и сведениями об источнике.

Схема хранится в `catalog/schema.sql`. Чтобы пересобрать базу из `recipes.json` и `catalog/seed_localization.json`, выполни:

```powershell
& '.\.venv\Scripts\python.exe' -m tools.seed_catalog
```

Скрипт собирает базу во временном файле и заменяет рабочую копию после успешного импорта.

## Пилот Wikibooks

Пилот проверяет, сколько страниц из русской и английской кулинарных книг можно разобрать автоматически. В выборку по умолчанию попадает по 75 страниц из каждой категории. Скрипт сохраняет снимок с точными ревизиями и строит отдельную базу.

```powershell
& '.\.venv\Scripts\python.exe' -m pip install mwparserfromhell==0.7.2
& '.\.venv\Scripts\python.exe' -m tools.build_pilot fetch --contact 'your-contact@example.org'
& '.\.venv\Scripts\python.exe' -m tools.build_pilot build
```

Подставь свой контакт для заголовка запроса к Wikimedia. Для повторной сборки на сохранённой выборке достаточно команды `build`. Она выполняется локально. Параметры выборки можно посмотреть через `fetch --help`.

В папке `catalog/pilot/` сохраняются:

- `snapshot.json` — выбранные ревизии с оригинальной разметкой, датой загрузки и лицензией сайта.
- `pilot.sqlite` — одна строка на страницу. Списки состава и шагов сохраняются с заголовками разделов. Нестандартные длительности и выход блюда остаются в исходных полях для разбора. Для каждой страницы есть ссылка на её ревизию и флаги проверки.
- `report.json` — число извлечённых полей по языкам, причины пропусков и контрольные суммы. Показатель `all_four` считает страницы с извлечёнными составом, шагами, временем и порциями. Это показатель покрытия парсера. Перед выпуском данные потребуют нормализации и проверки источников.

Текст кулинарных книг Wikibooks предоставляется на условиях, указанных в источнике. Снимок сохраняет ссылки и оригинальные примечания для проверки атрибуции. [Условия Wikimedia](https://foundation.wikimedia.org/wiki/Policy:Terms_of_Use#7._Licensing_of_Content)

## Сборка каталога из снимков

После загрузки пилотного снимка запусти из корня проекта:

```powershell
& '.\.venv\Scripts\python.exe' -m tools.build_catalog
```

Сборщик работает офлайн. По умолчанию он читает `catalog/pilot/snapshot.json`. Для других снимков укажи `--snapshot ПУТЬ` для каждого файла. Если одна страница встречается несколько раз, используется её последняя ревизия.

- `dist-data/recipes.sqlite` содержит рецепты на языке источника, состав, шаги, время, порции и ссылки на точные ревизии. Однозначные килограммы и литры приводятся к граммам и миллилитрам. Дроби и простые диапазоны записываются числовыми границами. Исходная строка ингредиента сохраняется.
- `dist-data/report.json` перечисляет отклонённые страницы и причины, подсчитывает пробелы в данных и строки ингредиентов, которым требуется сопоставление или проверка. Точные совпадения состава, шагов и метаданных внутри одного языка объединяются с сохранением обеих ссылок на источники.
- `dist-data/manifest.json` хранит версию схемы, версию данных и контрольные суммы входных снимков, правил и выходных файлов.

Правила сопоставления хранятся в `catalog/normalization.json`. Подготовленный каталог используется для дальнейшей проверки, перевода и группировки. Для запуска MVP используется его двуязычный `catalog/recipes.sqlite`.

## Переводы, восстановление и обобщение

На ПК запусти локальный [llama.cpp](https://github.com/ggml-org/llama.cpp) с моделью [Qwen3-4B GGUF](https://huggingface.co/Qwen/Qwen3-4B-GGUF). Параметры для локальной сборки каталога:

```powershell
llama-server -m Qwen3-4B-Q4_K_M.gguf -ngl 99 -c 16384 -np 2 --host 127.0.0.1 --port 8789 --alias qwen3-4b --reasoning off
& '.\.venv\Scripts\python.exe' -m tools.enrich_catalog
& '.\.venv\Scripts\python.exe' -m tools.export_android
```

`enrich_catalog` проверяет размер и порядок списков, числовые количества, язык и термины из кулинарного словаря. Пропущенные шаги извлекаются из распознанных разделов и подписей исходной страницы. Предположения ИИ сохраняются отдельно с пометкой для проверки и ссылкой на исходную ревизию. Кандидаты на объединение сравниваются по названию, составу и способу приготовления, а модель обобщает только общие признаки подтверждённых групп.

Для расширенного каталога передай `--prepared`, все использованные на этапе 3 `--snapshot` и отдельный `--output-dir`. Укажи этот каталог в `tools.export_android --enriched ПУТЬ`. Повторная сборка с `--cache-only` читает сохранённые ответы модели.

Экспорт включает двуязычные записи с пройденными проверками структуры, источника и сопоставимых единиц. Неподтверждённые дополнения остаются в базе и отчёте этапа 4. Каталог доступен по названию, а строгий подбор использует записи с известным временем и сопоставимым составом.

## Разметка и расширение каталога Android

Файл `catalog/pilot_tags.json` хранит двуязычные названия тегов, их постоянные ID и ручную разметку пилота. Ручная разметка сохраняет приоритет. Для новых рецептов `tools.infer_recipe_tags` ставит теги по исходному названию, составу и шагам. Если признаков недостаточно, категория остаётся пустой. Для сложности хранится пояснение на русском и английском. Необычность и сытность — оценки для подбора блюд.

Расширенную базу из трёх сохранённых снимков можно собрать из корня проекта. Для этого нужны CTranslate2, SentencePiece и локальные веса M2M100 в `.venv/local-ai/m2m100`. Для машины без CUDA используй `--mt-device cpu`.

```powershell
& '.\.venv\Scripts\python.exe' -m tools.enrich_catalog `
  --prepared dist-data/release-input --snapshot catalog/pilot/expanded/snapshot.json `
  --snapshot catalog/pilot/additional/snapshot.json --snapshot catalog/pilot/snapshot.json `
  --output-dir dist-data/discovery-enriched --cache dist-data/stage4/model-cache.sqlite `
  --cache-only --mt-models .venv/local-ai/m2m100 --mt-device cuda
& '.\.venv\Scripts\python.exe' -m tools.export_android --enriched dist-data/discovery-enriched
```

Экспорт пропускает записи с выявленными проблемами перевода или источника и добавляет теги к принятым записям. Чтобы обновить только разметку уже собранного Android-каталога, выполни:

```powershell
& '.\.venv\Scripts\python.exe' -m tools.tag_catalog
```

Команда работает офлайн. Она обновляет таблицы `tag_axis`, `tag` и `recipe_tag` в `dist-data/android/recipes.sqlite`. Манифест хранит версию правил, числа рецептов с ручной и автоматической разметкой и покрытие по категориям.

## Поиск блюд

Строка поиска предлагает названия и теги при вводе. Название можно сочетать с тегами и лимитом времени. Панель над выдачей остаётся на экране при прокрутке. Чтобы снять условие, нажми на его метку. К готовым сценариям можно вернуться через «Идеи».

Поиск учитывает названия на русском и английском. Для точного совпадения рецепт должен иметь хотя бы один выбранный тег в каждой выбранной категории. Если точных совпадений нет, приложение предлагает изменить одно условие и показывает, сколько карточек это даст. Отдельно отображаются близкие варианты, которым не хватает одной категории при совпадении хотя бы с одной.

При заданном времени поиск учитывает рецепты с известной длительностью в пределах лимита. Он сортирует совпадения по времени, ставит неизвестную длительность в конец и объединяет варианты в карточки до разбиения на страницы. Возврат из рецепта сохраняет запрос, фильтры и позицию в выдаче.

## Проверка Android

`tools/verify_android.py` устанавливает APK через ADB и проверяет подбор по тегам, поиск по продуктам, переключение языка, порции, офлайн-каталог и отображение атрибуции. Для проверки чистой установки и авиарежима подходит Android-эмулятор.

## Ранний прототип

`app.py`, `index.html` и тесты MVP служат контрольной реализацией стартового подбора. Пользовательский выпуск собирается из проекта `android`.

## Проверка

Для тестов сборщика установи `mwparserfromhell==0.7.2` в `.venv`, как описано в разделе о пилоте.

```powershell
& '.\.venv\Scripts\python.exe' -m unittest -v
```

Тесты покрывают перенос каталога, связь русских и английских записей, фильтрацию, группировку, пересчёт порций и обработку недоступного или некорректного ответа модели. Для сценариев ИИ используется подставной ответ Ollama.
